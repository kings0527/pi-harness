# 反漂移纪律（Anti-Drift Discipline）

适用于一切"在混沌中定位目标"的任务：逆向分析、故障诊断、漏洞挖掘、数据溯源、根因分析。

---

## 铁律：三次即换

同一方法失败 3 次，MUST 切换路径。不允许第 4 次"微调重试"。
失败的定义：没有产生**新信息**。重复的报错、相同的空结果、一样的崩溃——都是失败。

---

## 层级锁定

开始前 MUST 声明当前工作层级：

```
检测层 → 保护层 → 逻辑层 → 数据层
```

在一个层级内工作时，禁止跨层操作。发现问题在另一层，MUST 显式声明"切换到 X 层"，说明原因，再动手。

违规信号：你正在同时处理两个层的问题（比如一边绕检测一边分析算法）。立即停下，选一个。

---

## 收敛不发散

每一步行动 MUST 缩小搜索空间。如果一步操作之后，可能性没有减少，这步就是浪费。

合格的一步：
- 排除了一个假设
- 定位到更精确的范围（从模块→函数→行）
- 获得了一个之前未知的约束条件

不合格的一步：
- "看看这个函数做什么"（无假设驱动）
- "试试另一个参数"（无理论支撑）
- "多读点代码理解一下"（无终止条件）

---

## 假设驱动

禁止无目的探索。每次行动前 MUST 有一个可证伪假设：

```
假设：[具体猜测]
验证方法：[一个动作]
如果成立：[下一步]
如果不成立：[排除什么，换什么方向]
```

没写出这四行就动手 = 漂移。

---

## 30 分钟熔断

单一子问题持续 30 分钟无进展（无新信息产出），MUST 触发：

1. 退一步：当前假设是否已被隐式证伪？
2. 换一层：问题是否在更深/更浅的层？
3. 换工具：当前工具是否不适合这个问题？
4. 缩范围：能否只解决目标的 70% 先交付？

如果四个问题都回答了还没路，声明"阻塞"并停下。

---

## 进度锚点

每完成一个有效步骤，MUST 记录：

```
已知：[到目前为止确认的事实]
排除：[已证伪的假设]
当前假设：[正在验证什么]
下一步：[具体动作]
```

这不是文档——这是你的定位锚。漂移就是丢了这个锚。
